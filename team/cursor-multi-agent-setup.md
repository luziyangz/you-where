# Cursor 多代理初始环境说明

## 1. 目标
- 建立一个真实团队式多代理协作环境。
- Leader 负责统筹、分发、审核和节奏控制。
- 子代理独立执行并仅汇报结果，不共享上下文。

## 2. 代理与模型分配
- Leader（总负责人）：
  - 模型定位：强模型（由你在发起任务时指定高能力模型）
  - 职责：任务拆分、验收标准、冲突协调、最终审批
- Frontend 子代理：
  - 模型：Gemini
  - 职责：前端页面、交互、样式与小程序体验实现
- Backend 子代理：
  - 模型：Sonnet 4.6
  - 职责：后端接口、数据层、服务层与稳定性实现
- Analyst 子代理（可多个）：
  - 模型：Auto
  - 职责：方案评审、风险分析、回归检查、文档审计

## 3. 协作协议
1. Leader 发出任务卡（目标、范围、验收标准、截止条件）。
2. 子代理独立执行，不共享上下文。
3. 子代理仅输出：
   - 结果摘要
   - 关键改动
   - 风险与阻塞
   - 验证结论
4. Leader 汇总并复核，必要时发起二次任务。
5. 收口后更新全局和各代理 `待办.md`、`已办.md`。

## 4. 汇报模板（子代理）
- 任务编号：
- 完成状态：完成 / 部分完成 / 阻塞
- 改动产物：
- 验证结果：
- 风险与待确认：
- 建议下一步：

## 5. 文件约定
- 公司统一规则：
  - `.cursor/rules/multi-agent-company.mdc`
- 全局协作记录：
  - `待办.md`
  - `已办.md`
  - `record.md`
  - `team/current-plan.md`
- 代理独立记录（每个代理各自维护）：
  - `team/leader-待办.md`
  - `team/leader-已办.md`
  - `team/frontend-gemini-待办.md`
  - `team/frontend-gemini-已办.md`
  - `team/backend-sonnet46-待办.md`
  - `team/backend-sonnet46-已办.md`
  - `team/analyst-auto-待办.md`
  - `team/analyst-auto-已办.md`

## 6. 启动建议
- 第 1 步：Leader 建立本轮任务卡并拆分前端/后端/分析子任务。
- 第 2 步：子代理并行执行，按模板回报。
- 第 3 步：Leader 审核并合并结论，更新全局与代理记录文件。

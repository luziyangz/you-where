# 「你在哪页儿」当前版本产品文档

## 1. 文档信息

- 产品名称：你在哪页儿
- 产品形态：微信小程序 + FastAPI 后端
- 当前版本定位：双人共读陪伴小程序，支持绑定伙伴、共同选书、导入 TXT、站内阅读、记录进度、回复互动、阅读历史、目标和提醒配置。
- 文档范围：基于当前代码实现整理，覆盖已存在页面、业务逻辑、权限规则、接口能力和测试/审核辅助能力。
- 非本文范围：未来商业化、多人小组、AI 解读、复杂社区、排行榜、课程售卖等尚未实现功能。

## 2. 产品定位

「你在哪页儿」是一款面向情侣、朋友、学习搭子的双人共读小程序。产品核心不是泛书城，也不是单人阅读器，而是围绕一个固定伙伴建立轻量、持续、有反馈的共读关系。

用户可以登录后绑定一名伙伴，双方共同选择或导入一本书，在站内阅读、同步页码、记录想法、查看和回复对方的笔记。产品强调“我和 TA 正在一起读到哪里”，而不是单人读书效率。

## 3. 用户角色

### 3.1 普通用户

- 使用微信身份登录。
- 可查看自己的共读码。
- 可绑定一名共读伙伴。
- 可浏览书房、导入 TXT、加入共读、阅读正文、记录进度、回复伙伴笔记。

### 3.2 共读伙伴

- 与当前用户形成一对一 active pair。
- 与申请方拥有同一本共读书的相同阅读权限。
- 对加入共读、换书、解绑等关键行为可参与同意流程。

### 3.3 微信审核用户

- 通过“审核测试登录”入口使用账号密码登录。
- 由 `ENABLE_REVIEW_LOGIN`、`WECHAT_REVIEW_ACCOUNT`、`WECHAT_REVIEW_PASSWORD` 控制。
- 固定审核用户共读码为 `900003`。
- 该入口仅开发版/体验版展示，正式版隐藏。

### 3.4 隐藏测试用户

- 固定共读码：`900001`、`900002`。
- 通过后端种子脚本写入真实用户表，不在小程序界面展示测试用户入口。
- 普通用户可输入这两个共读码进行绑定测试。
- 当前规则：只要共读关系中任一方是 `900001` 或 `900002`，绑定、加入共读、换书、解绑等需要对方同意的操作默认成功。

## 4. 核心业务闭环

```text
打开小程序
-> 微信登录 / 审核登录
-> 同意用户协议与隐私指引
-> 查看首页共读状态
-> 绑定伙伴
-> 浏览书房或导入 TXT
-> 加入共读
-> 阅读正文
-> 记录页码和笔记
-> 伙伴查看、回复、同步进度
-> 查看历史、目标、提醒和个人资料
```

## 6. 登录与账户体系

### 6.1 微信登录

用户通过微信登录获得后端 session token。后端使用 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET` 换取 open_id。未配置微信密钥时，正式环境不能使用真实微信登录。

登录成功后前端保存：

- `token`
- `user`
- `pair`
- `currentBook`

全局由 `app.js` 恢复 session，并在登录失效时清理状态。

### 6.2 协议与隐私

用户登录后需要同意用户协议和隐私保护指引。涉及微信隐私接口的能力包括：

- 从聊天记录选择 TXT 文件
- 复制共读码
- 保存二维码到相册
- 订阅消息授权

小程序开启 `__usePrivacyCheck__`，并通过统一隐私授权页处理微信隐私授权 pending 场景。

### 6.3 审核测试登录

首页和我的页在开发版/体验版展示“审核测试登录”。审核员输入账号密码后登录固定审核用户。若服务器容器未注入 `ENABLE_REVIEW_LOGIN=1`，接口会返回“审核入口未启用”。

### 6.4 测试用户

生产默认关闭 `/auth/test-login`。云端真实测试方式是使用种子脚本写入隐藏测试用户，然后让真实微信账号绑定 `900001` 或 `900002`。

## 7. 首页

页面：`pages/home/index`

### 7.1 未登录状态

展示产品价值、登录入口、协议勾选和隐私授权状态。非首页业务 Tab 在未登录时会被拦截。

主要操作：

- 微信一键登录
- 审核测试登录（开发版/体验版）
- 查看用户协议和隐私政策

### 7.2 已登录未绑定

首页提示用户尚未绑定伙伴，引导进入结伴页。

业务逻辑：

- 从 `/home` 获取用户、pair、当前书和待处理申请。
- 无 active pair 时展示绑定引导。

### 7.3 已绑定无书

展示伙伴关系，引导去书房选择或导入书籍。

### 7.4 已绑定有书

展示当前共读书、双方阅读状态、继续阅读入口和去记录入口。

当前书若存在 `catalog_id`，可直接跳转阅读器；手动创建且无正文的书则进入记录页。

### 7.5 绑定/换书/解绑申请处理

首页会展示待处理的绑定、解绑、换书申请。用户可同意或拒绝。

## 8. 结伴页

页面：`pages/partner/index`

### 8.1 未绑定状态

展示：

- 我的共读码
- 复制共读码
- 共读二维码
- 手动输入对方共读码
- 扫一扫绑定

二维码内容格式支持：

- `youzainaye://pair/bind?join_code=xxxxxx`
- URL query 中的 `join_code`
- JSON 文本中的 `join_code`
- 纯 6 位数字

### 8.2 绑定规则

- 用户不能绑定自己的共读码。
- 对方不存在时提示共读码无效。
- 任一方已有 active pair 时不能再绑定。
- 同一时间，申请方只能向一个人发送绑定申请；该申请未处理前不能向其他人发申请。
- 重复绑定同一个人时返回已有 pending 申请。
- 普通用户绑定普通用户时默认生成绑定申请，需对方同意。
- 与 `900001` 或 `900002` 相关的绑定默认成功。

### 8.3 已绑定状态

展示：

- 伙伴昵称、头像
- 结伴天数
- 当前共读书
- 共同笔记数、书籍数
- 解绑入口

### 8.4 解绑规则

- 普通 pair 解绑默认生成解绑申请，需对方同意。
- 对方发起解绑时，当前用户需处理。
- 满足强制解绑条件时可强制解除，强制解除会写入 pair block，防止再次绑定。
- 与 `900001` 或 `900002` 相关的解绑默认成功，不生成申请。

## 9. 书房

页面：`pages/bookstore/index`

### 9.1 页面功能

书房提供：

- 分类浏览
- 书名/作者搜索
- 收藏书架
- 最近阅读
- 从微信聊天记录导入 TXT
- 导入网页/TXT 链接
- 进入书籍详情

### 9.2 书籍来源

当前支持：

- 内置推荐书目
- Project Gutenberg 公版书
- Gutendex 中文书目同步
- 用户上传 TXT
- 用户导入阅读链接
- 运营导入 manifest 书单

### 9.3 TXT 导入

入口：「从聊天记录导入 TXT」

流程：

1. 点击导入按钮。
2. 若微信要求隐私授权，先完成隐私授权。
3. 调起 `wx.chooseMessageFile`。
4. 用户在微信中选择聊天对象和会话内 TXT 文件。
5. 选中文件后回到小程序。
6. 小程序弹出“确认导入 TXT”原生确认框。
7. 用户点击“导入”后上传。
8. 后端解析文本并生成私有 catalog。
9. 导入成功后跳转书籍详情。

权限规则：

- TXT 导入生成的书目 `owner_user_id` 为上传者。
- 未加入共读前，仅上传者可阅读。
- 一旦加入当前 active pair，pair 双方都可阅读详情、正文、目录、进度、划线。

微信后台要求：

- 必须在用户隐私保护指引中声明“选中的文件”。
- 否则 `wx.chooseMessageFile` 会失败，错误为 `api scope is not declared in the privacy agreement`。

### 9.4 导入链接

用户可输入：

- 书名
- 作者
- TXT 或网页 URL
- 预估页数

后端优先尝试提取正文。若能提取正文，则生成站内全文；否则保存为外链书目。

安全约束：

- 拒绝私网地址。
- 限制内容大小。
- 对文本进行编码识别和中文规范化。

## 11. 阅读器

页面：`pages/reader/index`

### 11.1 阅读能力

- 按页读取站内正文。
- 支持页面缓存。
- 支持章节目录。
- 支持跳页。
- 支持阅读主题、字号、亮度。
- 支持进度保存。
- 支持划线/标注。
- 支持从阅读器同步当前页到共读进度。

### 11.2 权限

阅读接口以 catalog 权限为准：

- 公共书籍登录后可读。
- 用户私有 TXT 仅 owner 或已加入该共读关系的伙伴可读。
- 不是当前 active pair 成员时不能读 pair 私有书。

### 11.3 与共读进度关系

阅读器可读取当前 active pair 和 current book。若阅读的 catalog 是当前共读书，保存进度时会同步到共读书进度；否则仅保存个人书城阅读进度。

## 12. 我们的记录

页面：`pages/progress/index`

### 12.1 页面职责

展示当前共读书的双人进度、笔记流、回复、未读提示和补记入口。

### 12.2 记录进度

用户可提交：

- 页码
- 笔记内容
- 引用原文
- 是否标记读完

业务规则：

- 页码必须在 1 到总页数之间。
- 页码不能小于当前已记录页码。
- 记录写入 `entries`。
- 进度由 book progress、entry 最高页和阅读器进度综合计算。
- 双方均达到末页时，书籍状态变为 finished。

### 12.3 笔记权限

- 自己的笔记完整可见。
- 伙伴笔记若页码高于自己当前进度，则显示锁定状态。
- 未解锁笔记不能回复。
- 已解锁笔记可单层回复。

### 12.4 未读

页面会维护 read mark。用户打开记录页后可标记已读，减少未读提示。

### 12.5 分享到书友书摘

用户可把自己的 entry 发布到书友书摘。发布后可在圈子/书友书摘页展示，并可微信转发。

## 20. 权限与安全规则

### 20.1 登录门禁

主业务页需要登录。未登录访问非首页 Tab 时，前端阻止跳转并提示登录。

### 20.2 Pair 权限

与共读相关的书籍、记录、回复只能由 active pair 成员操作。

### 20.3 私有书目权限

私有 TXT/链接书目默认仅 owner 可访问。加入 active pair 后，pair 双方拥有相同阅读权限。

### 20.4 绑定申请约束

同一用户同一时间只能向一个人发送绑定申请。已有未处理申请时，不能再向其他人发送申请。

### 20.5 并发保护

后端使用命名锁和 active lock 表处理：

- 绑定并发
- 当前 active pair 唯一性
- 当前 active book 唯一性
- 换书并发

### 20.6 导入安全

导入 URL 拒绝私网地址，限制内容大小。上传 TXT 做编码识别和正文规范化。

## 22. 当前已修复的重要业务规则

- `900001/900002` 测试共读码相关同意流程默认成功。
- 同一时间只能向一个人发送绑定申请。
- 私有 TXT 加入共读后，申请方和被申请方拥有相同阅读权限。
- 微信聊天记录 TXT 导入在选中文件后弹原生确认框，避免真机无确认按钮的问题。
- 审核登录配置已补充 Docker Compose 环境变量传递。
- 微信 `chooseMessageFile` 失败时可明确提示隐私后台缺少“选中的文件”声明。

## 23. 当前已知限制

- 微信订阅消息真实投递仍依赖线上模板、授权和计划任务。
- 微信手机号授权、保存二维码到相册、聊天文件选择需要真机验证。
- 书友书摘当前是轻量内容发现，不是完整社区。
- 测试用户 A/B 不应在小程序界面展示，只能通过种子脚本和共读码使用。
- 后端接口统一返回 `200 + code` 包装较多，尚未完全 REST 化。
